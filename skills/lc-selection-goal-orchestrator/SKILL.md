# 经营目标选品编排器

## 目标

只维护一个经营项目。选品方法以独立Skill存在，每次运行以统一数据库中的任务、候选、证据和方法运行记录存在；每天只发送一份早报和一份晚报。

## 必读规则

执行前完整读取 [references/schedule.md](references/schedule.md)。调用方法时复用现有 `$amazon-keyword-selection`、`$amazon-competitor-store-selection`、`$amazon-software-product-selection`、`$amazon-cross-platform-selection`、`$lc-1688-channel-closure` 和 `$lc-fbm-shared-pool-selection`。

## 编排顺序

1. 读取年度净利目标、固定费用、渠道实际单均利润、当前订单、稳定款、流失款、剩余月份和剩余工作日。
2. 计算每日贡献目标、各渠道所需日单、稳定款缺口和需要的成熟测试量。
3. 判断数据成熟度。前60—90天或成熟样本不足时使用固定基线，不伪造动态成功率。
4. 按星期只调用当天轮到的方法；共享FBM池、成交信号、去重和异常检查每个工作日运行。
5. 合并相同候选的多方法证据，保持唯一候选主档，并执行国家、品牌和平台门禁。
6. 幂等生成当天统一任务；同日同模板不得重复创建。
7. 09:00生成一份早报，19:00生成一份验收；周日20:00生成一份周报。
8. 满足成熟期后，按最终稳定款、实际利润和库存损失评估方法效率，并仅调整未来建议投入。

## 目标倒推

使用以下口径：

```text
每日贡献目标 = (年度净利目标 + 固定费用) / 365
渠道所需日单 = 分配给该渠道的每日贡献目标 / 实际单均贡献利润
所需稳定款 = 渠道所需日单 / 稳定款单款日均订单
稳定款缺口 = max(0, 所需稳定款 - 当前有效稳定款 + 预计流失替换)
每日测试需求 = 稳定款缺口 / 成熟转化率 / 剩余工作日
```

若实际利润、成熟转化率或稳定款日均订单缺失，明确输出“缺少输入”，并回退固定基线。

## 方法效率

方法效率不能按候选量排序。至少综合：成熟候选产生的稳定款、稳定款实际贡献利润、库存损失、重复率和证据完整度。未成熟方法保留“观察中”，不得提前定为高效。

## 状态与边界

- 方法可独立启用、暂停、阻塞和复查。
- 登录过期、验证码、缺文件或接口异常只阻塞该方法，不阻断其他方法。
- 只生成候选、评分、任务、验收和补货建议。
- 最终侵权/版权/专利、品牌归属、发布、采购、调价、补货和真实货件必须人工确认或执行。
