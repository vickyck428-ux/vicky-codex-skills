# 清货规则 v1.1

业务规则只有一个实现源：`scripts/clearance_math.cjs`。纯 JS 计算和 Excel 公式均从该模块生成；工作簿生成器不得另写一套规则。

## 计算

- 分段日销：
  - 最近 7 天：`units_7d / 7`
  - 第 8–15 天：`(units_15d - units_7d) / 8`
  - 第 16–30 天：`(units_30d - units_15d) / 15`
- 加权日销 `A`：三段按 `50% / 30% / 20%` 加权；缺失段不参与并重新归一化。
- 趋势 `T = 最近15天 / 前15天`。前期为 0 时使用 `1.0` 并降低风险判断置信度。
- `B1 = clamp(T, 0.8, 1.2)`；`B2 = clamp(T, 0.7, 1.3)`。
- `H = A × B1 × (C + D + E) × N`。
- 下一周期目标：`H + A × B2 × F`。
- FBA 目标库存：`min(下一周期目标, A × 90)`。
- FBA 供给天数：`FBA可售 / (A × B1)`；`A=0` 且有库存时视为无限。
- 潜在超量数量：`max(0, FBA可售 - FBA目标库存)`。
- 费用风险数量：`max(0, 下一快照计费数量 - A × 距费用日天数)`。
- 清货目标数量：
  - 紧急清退、主动清货：`min(FBA可售, ceil(max(潜在超量, 费用风险)))`
  - 停补观察、待补货、健康维持：`0`
  - FBA 可售未知：空白

课程默认参数为 `C=7、D=2、E=35、F=7、N=1.2`；只作为默认值，运行时可覆盖。

## 五种主状态

按顺序命中第一项：

1. 紧急清退
   - stranded 或不可售数量大于 0；
   - 费用快照日前预计无法消化的数量大于 0；
   - 已有预计库龄附加费且存在潜在超量。
2. 主动清货
   - 最老库龄至少 110 天且预计不能在 181 天前卖完；
   - 供给天数超过 90 天且趋势不增长；
   - 近 60 天零销量且有库存和明显库龄。
3. 停补观察
   - 关键库存、库龄、费用日或销量数据不足；
   - 趋势 `T < 0.8`；
   - 库存高于动态目标但未达到主动清货条件；
   - 库存低于目标但连续需求未得到证明。
4. 待补货
   - 库存低于下一周期目标；
   - 三个销量分段均有销量，或 `long_tail_approved=是`；
   - 不属于前三类。
5. 健康维持
   - 其余无明显风险 SKU。

已知 stranded、不可售或费用风险优先于缺项预警；但库存未知时清货目标仍为空。

## 数量状态与置信度

- `数量状态`
  - `已计算`：FBA库存和贡献利润均已提供。
  - `暂定-缺经济数据`：FBA库存已知，但贡献利润缺失。
  - `需要人工确认-缺库存`：FBA可售未知，清货目标为空。
- `风险判断置信度`：只评价销量、库存、库龄和费用日，不因缺成本自动降级。
- `经济性置信度`
  - 高：贡献利润、外部回收价、移除成本均齐；
  - 中：有贡献利润，或落地成本与 Amazon 单件费用均齐；
  - 低：其余情况。

## 分阶段动作

- 紧急清退：立即比较 Outlet、移除、外部销售、FBA Liquidations、弃置或捐赠。
- 主动清货：停止采购；修复页面和流量；轻促销 7–14 天；无改善再扩大折扣或转退出渠道。
- 停补观察：停止新采购，7–14 天复查；只保留能证明转化的广告。
- 健康维持：不改变采购和价格，仅按复查周期更新。
- 待补货：转交 `$amazon-inventory-shipping`，本 Skill 不给采购数量。

清算回收区间仅为毛回收估算。没有完整成本和当前渠道报价时，不给净回收承诺。
